# Birding

The Harker Ornithology Report, served at `/birds/`: a personal birding
project built on Cornell Lab tools and services (eBird, Macaulay Library,
Merlin Bird ID). A Next.js app turns exported eBird data into a browsable
report — map, location index, checklists, media and written field notes.

## Layout

- **`web/`** — the app: Next.js, exported as fully static HTML with
  `basePath: '/birds'`. There is no server and no database; every page is
  pre-rendered at build time into `web/out/`, which the repository's build
  publishes at `/birds/`.
- **`observation-data/`** — the eBird CSV exports that power the site
  (`ebird-data-latest.csv`, `ebird-media-latest.csv`), and earlier exports in
  `archive/`.
- **`web/field-notes/`** — Markdown trip reports rendered in the Field Notes
  section, one file per note.
- **`notebook/`** — personal trip-planning notes and field-guide PDFs;
  reference material, not used by the site. The folder stays on disk and out
  of the repository: the notes are personal, the guides third-party.

[`user_guide.md`](user_guide.md) is the non-developer's guide to editing every
part of the site; [`web/AGENTS.md`](web/AGENTS.md) is the working brief for
coding agents.

## What builds each part of the page

| Source | What it produces |
|---|---|
| `observation-data/ebird-data-latest.csv` | Map pins, the location index, species tables, and one page per checklist. |
| `observation-data/ebird-media-latest.csv` | The Media section and the photo lightboxes. |
| `web/field-notes/field-note-*.md` | The Field Notes section. |
| `web/src/lib/siteConfig.ts` | Site title, subtitle, byline, the abstract, the off-site links, and the links to the rest of felipeharker.org. |

Observations are never written into markup — a change to a bird, a place or a
count is a change to a CSV. The project's own settings are the exception, and
they live in one module rather than in a config file beside it.

## Running the app locally

```bash
cd web/birds/web
npm install
npm run dev      # http://localhost:3000/birds/
npm run build    # static export into web/out/
npm run lint
```

`npm run dev` serves this app alone, so its links to the rest of
felipeharker.org 404 there. To see it inside the whole site, build it and run
`node tools/serve.mjs` from the repository root (http://localhost:8000/birds/).

## Updating data

Drop new eBird exports into `observation-data/`, replacing
`ebird-data-latest.csv` / `ebird-media-latest.csv`, and move the previous
ones to `archive/` if you want to keep them. Rebuild and the whole report
follows — the map, the location index, the species tables, and one generated
page per checklist.

## Deploy

Nothing here deploys on its own. The repository's `tools/build.mjs` runs
`npm ci && npm run build` in `web/` (the build reads `../observation-data`,
so it runs from `web/`) and copies `web/out/` to `dist/birds/`; Render
publishes `dist/` as felipeharker.org.

## Source layout

```
web/
  field-notes/           Markdown trip reports, one file per note
  src/app/
    hark.css               the shared standard — generated by predev/prebuild, git-ignored
    styles_primary.css     this site's own components, commented throughout
    styles_map.css         all map styling (frame, pins, MapLibre chrome)
    layout.tsx             fonts and metadata
    page.tsx               reads every content source, hands it to HomeDocument
    checklist/[id]/        one static page per submitted checklist
  src/components/        HomeDocument, ChecklistDocument, Map, ImageLightbox
    ui/                    shared primitives: Section, Masthead, Colophon, MediaGrid, Nav, Icons
  src/lib/
    parseEbird.ts          reads both eBird CSVs (server only — it touches the filesystem)
    parseFieldNotes.ts     reads field-notes/*.md
    siteConfig.ts          title, abstract, off-site links, the rest of felipeharker.org
    formatDate.ts          eBird's two date formats → one display format
```

## Design

The report shares one visual language with every page on felipeharker.org:
Inter for headings and prose, IBM Plex Mono reserved for recorded data,
hairline rules and whitespace instead of heavy bars and boxes, three type
weights and no bold, and one deep-red accent that only ever means
"interactive or selected". Nothing is numbered.

The standard is `web/standards/` in this repository, rendered at
`/standards/`. Its stylesheet is copied into `web/src/app/hark.css` before
every dev server, build and lint — never edit that copy. This app's own rules
are in `styles_primary.css` and `styles_map.css`; restyling means changing a
token, not hunting through rules. There is no CSS framework and no inline
style objects.
